# 系统专用软件说明书写作约束

本目录用于保存 `copyright/manuals/<copyright-id>.md`。说明书是文档鉴别材料的正文来源，生成器不会用通用模板补足内容。

## 1. 必须满足的内容条件

1. 内容只能描述本软著对应系统已经具备的功能、模块、页面、接口、数据和操作流程。
2. 说明应覆盖适用范围、角色与权限、运行环境、功能入口、输入条件、操作步骤、处理状态、输出结果、异常恢复和验收方式。
3. 每个操作项应说明对象和前置条件，避免只有“点击保存”“查看结果”等脱离系统语境的短句。
4. Markdown 应使用稳定的章节层级，并使用 `1.`、`1.1`、`（1）` 等编号组织操作步骤。
5. 必须包含“补充操作提示”章节；该章节及其后的所有内容必须分段、编号，不能循环复用相同段落。
6. 转换为打印行后至少要有1800个非空正文行，才能形成60页、每页30行的材料。内容不足时应继续补充真实的业务说明，而不是复制段落。

## 2. 《软件的主要功能》来源

`copyright/config/copyrights.yaml` 中每个软著的 `description` 字段会作为《软件的主要功能》，去除空白后必须为500至1300字。该字段应概括真实的目标用户、业务对象、核心模块、主要流程、输入输出、异常处理和可追溯能力。

## 3. 推荐结构

```markdown
# <软件名称>软件说明书

## 一、软件概述

## 二、用户角色与使用边界

## 三、运行环境与启动方式

## 四、核心功能操作

### 4.1 <具体功能名称>

1. <前置检查>
2. <输入与参数>
3. <执行步骤>
4. <结果核验>
5. <异常恢复>

## 五、数据、接口与输出说明

## 六、权限、安全与审计

## 七、常见问题与故障排查

## 八、补充操作提示

### 8.1 <具体且不重复的提示主题>
```

上述代码块只定义结构，不是可用于补页的正文。提交前运行：

```bash
python copyright_cli.py generate <copyright-id> --manual copyright/manuals/<copyright-id>.md
python copyright_cli.py material-audit copyright/outputs/<copyright-id>
```
